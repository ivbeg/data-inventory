# Шаблоны

Шаблоны собраны из глав о процессе. Скачайте подходящий и заполните; строки-примеры можно удалить. Файлы в кодировке UTF-8, разделитель — запятая.

## Реестр данных

[registry.csv](pathname:///templates/registry.csv) — 14 обязательных атрибутов из главы [«Реестр данных»](../03-process/05-registry.md) и расширенные. Колонки `title`, `description`, `format`, `issued`, `modified`, `license` и `publisher` названы как свойства DCAT-US v1.1 (бывшей схемы Project Open Data); у остальных названия свои, а их соответствие свойствам DCAT и DCAT-US — в главе [«Стандарты описания»](../05-frameworks/02-metadata-standards.md#сопоставление-с-реестром).

| Колонка | Атрибут |
|---------|---------|
| `id` | уникальный идентификатор |
| `title` | наименование |
| `description` | описание |
| `owner_person` | ответственный — сотрудник, который знает данные |
| `owner_contacts` | контакты ответственного |
| `update_frequency` | периодичность обновления: `continuous`, `daily`, `weekly`, `monthly`, `quarterly`, `annual`, `irregular`, `never`, `unknown` |
| `access_level` | режим доступа: `open`, `unstructured`, `restricted`, `closed`, `unknown` |
| `access_basis` | чем подтверждён режим доступа: ссылка, акт с пунктом, ответ владельца с датой; у `unknown` — что проверяли и из какой сети |
| `access_restriction` | причина ограничения: `personal_data`, `state_secret`, `official`, `confidential`, `third_party`, `owner_decision`, `none`, `unknown`, несколько — через «;» ([«Как записать»](../03-process/06-access.md#как-записать)) |
| `access_conditions` | условия доступа: кто, как, за сколько и за какой срок получает данные |
| `access_checked` | дата проверки режима доступа |
| `download_url` | ссылка для выгрузки — прямой адрес файла или интерфейса |
| `format` | формат распространения |
| `issued` | дата публикации |
| `modified` | дата последнего изменения данных |
| `quality_check` | отметка о контроле качества |
| `license` | условия использования |
| `publisher` | организация-владелец — идентификатор из [owners.csv](#владельцы-и-полномочия) или название |
| `domain` | домен, который ведёт запись в федеративном реестре, — идентификатор строки подразделения из [owners.csv](#владельцы-и-полномочия); пусто, если реестр ведёт одна команда ([«Как записать»](../05-frameworks/03-data-mesh.md#как-записать)) |
| `aliases` | синонимы — другие названия и прежние адреса, через «;» — расширенный состав |
| `type` | тип записи: `dataset`, `resource`, `system`, `site`, `group` |
| `schema` | схема данных или ссылка на описание полей |
| `data_contract` | ссылка на контракт данных или соглашение об уровне обслуживания; «нет», если его нет ([«Контракт данных»](../05-frameworks/03-data-mesh.md#контракт-данных)) |
| `information_system` | информационная система |
| `operator` | оператор системы |
| `mandate` | полномочие — идентификатор строки из [mandates.csv](#владельцы-и-полномочия) или формулировка |
| `legal_act` | нормативный акт |
| `personal_data` | есть ли персональные данные: `yes`, `no`, `unknown` |
| `related` | связанные записи — `aggregate_of:`, `copy_of:` или `successor_of:` и идентификатор, через «;» |
| `status` | статус записи: `active`, `retired`, `url_broken` ([«Как отметить в реестре»](../04-sources/06-legacy.md#как-отметить-в-реестре)) |
| `archive_url` | копия в веб-архиве — адрес копии с датой; у исчезнувшей записи — последняя копия, на которой источник ещё работал |
| `known_from` | откуда известно о наборе: метод и документ; если запись составила языковая модель — какая, когда и подтверждена ли запись ([«ИИ в инвентаризации»](../02-approaches/03-ai.md#5-записать-откуда-известно)) |
| `checked` | дата проверки записи |

В 14 обязательных колонках пустых ячеек нет: значение, «нет» — сведения не существует — или «не установлено» и где искать; в кодовых колонках — `unknown` ([«Если сведение не найдено»](../03-process/05-registry.md#если-сведение-не-найдено)). Первая строка-пример — запись реестра воздушных судов FAA из главы [«Реестр данных»](../03-process/05-registry.md#пример-записи), две другие — условный регистр медицинских работников и его агрегат.

[registry.schema.json](pathname:///templates/registry.schema.json) — схема шаблона в формате Table Schema из главы [«Реестр как данные»](../06-tools/03-registry-as-data.md#схема): 14 обязательных колонок, коды из справочников выше, идентификатор латиницей, цифрами и дефисами, даты по ISO 8601 или «нет» и «не установлено» с пояснением после тире, связи вида `aggregate_of:` и идентификатор. Проверка — `frictionless validate registry.csv --schema registry.schema.json`. Добавили свою колонку или код — допишите их и в схему. Ссылки на другие листы и правила между колонками — дата изменения не раньше даты публикации, состав у групп — схема не проверяет: их проверяют скриптом ([«Проверки»](../06-tools/03-registry-as-data.md#проверки)).

## Владельцы и полномочия

Два листа из главы [«Владельцы и полномочия»](../03-process/03-owners-and-mandates.md#как-записать):

- [owners.csv](pathname:///templates/owners.csv) — владельцы: идентификатор, полное и короткое название, уровень, слой данных (`government`, `public`, `commercial` — [«Как определить слой»](../04-sources/01-three-layers.md#как-определить-слой)), вышестоящая организация, подразделение и контакты, документ о полномочиях, статус (`active`, `abolished`) и преемник, дата проверки;
- [mandates.csv](pathname:///templates/mandates.csv) — полномочия: владелец, полномочие и дословная цитата, акт и пункт, ожидаемые данные, итог (`found`, `partial`, `not_found`, `transferred`), идентификаторы найденных систем и наборов, откуда известно, дата проверки.

Идентификатор строки из `mandates.csv` записывают в колонку `mandate` реестра, идентификатор владельца — в `owner` полномочия. Если реестр ведут домены, домен — строка подразделения с заполненными `parent` и `unit`, как `aircraft-registration` у FAA; её идентификатор идёт в колонку `domain` реестра ([«Data Mesh»](../05-frameworks/03-data-mesh.md#как-записать)).

## Опросный лист для владельцев

Два листа из главы [«Опросные листы и интервью»](../03-process/04-questionnaires.md#как-записать):

- [questionnaire.csv](pathname:///templates/questionnaire.csv) — анкета, по строке на набор: идентификатор, адресат, отметка владельца (`confirmed`, `corrected`, `new`, `not_ours`, `not_kept`, `needed`), откуда строка, если её вписали заранее, и ответы на [девять вопросов](../03-process/04-questionnaires.md#что-спрашивать) — система и где хранятся данные (`system`, `spreadsheet`, `document`, `email`, `paper`), набор, описание, ответственный, контакты, периодичность, откуда поступают данные, кому передаются, есть ли сведения о людях (`yes`, `no`, `unknown`), ограничения доступа и их основание, есть ли схема; комментарий и дата ответа;
- [respondents.csv](pathname:///templates/respondents.csv) — адресаты: владелец, подразделение, роль, адресат и контакты, даты отправки, напоминания, ответа и интервью, итог (`answered`, `no_data`, `refused`, `no_answer`, `redirected`) и кому переадресовано, дата проверки.

Идентификатор адресата записывают в колонку `respondent` анкеты, идентификатор владельца — в `owner` адресата. У строки, вписанной заранее, `id` совпадает с идентификатором записи реестра.

## Проверки качества

[quality-checks.csv](pathname:///templates/quality-checks.csv) — лист из главы [«Качество данных»](../03-process/07-quality.md#как-записать-в-реестр), по строке на проверку: идентификатор проверки, запись реестра, номер вопроса, если проверка нужна только ему, признак (`completeness`, `uniqueness`, `timeliness`, `validity`, `consistency`, `accuracy`, `format`, `fitness`), что проверяли, порог, результат, влияние (`none`, `caveat`, `blocking`) — для вопроса, если он указан, иначе для набора в целом, — дата данных, кто и когда проверял. Строки-примеры — проверки реестра воздушных судов FAA из главы [«Качество данных»](../03-process/07-quality.md#пример-проверки) и листа ожидания из условного примера.

Сводку записывают в колонку `quality_check` реестра, итог для пары «вопрос — набор» — в колонку `quality` листа «Связи» ниже.

## Карта данных

Для подхода «где найти нужное» — три листа из главы [«Интеллект-карты, доски и таблицы»](../06-tools/02-mindmaps-and-boards.md#рабочая-таблица):

- [sources.csv](pathname:///templates/sources.csv) — источники: тип, владелец, основание, уровень, слой данных (`government`, `public`, `commercial`), адрес, синонимы, первоисточник у копии (`copy_of` — идентификатор источника из того же листа) и откуда известно ([«Как записать»](../04-sources/01-three-layers.md#как-записать));
- [questions.csv](pathname:///templates/questions.csv) — вопросы с типовой темой, задачей и приоритетом ([«Как записать»](../03-process/02-goals-and-questions.md#как-записать));
- [links.csv](pathname:///templates/links.csv) — связи «вопрос — источник» с доступом, итогом проверки качества (`quality`: `fit`, `fit_with_caveats`, `unfit`, `not_checked`) и оговоркой к нему (`quality_note`) и датой ([«Годится ли для задачи»](../03-process/07-quality.md#годится-ли-для-задачи)).

И заготовка карты в формате атласа книги — [map.yaml](pathname:///templates/map.yaml); схема полей — [`data/README.md`](https://github.com/ivbeg/data-inventory/blob/main/data/README.md).

## Журнал поиска

[searches.csv](pathname:///templates/searches.csv) — лист из главы [«Поиск наборов данных»](../04-sources/05-dataset-search.md#как-записать), по строке на запрос: идентификатор, номер вопроса из `questions.csv`, поисковик или каталог, запрос дословно, язык, фильтры, дата, сколько результатов просмотрено, итог (`original` — найден первоисточник, `copy` — только копии, `lead` — след: система, владелец, каталог, `none` — ничего), идентификаторы найденных записей реестра или источников и пометка. Строки-примеры — поиски реестра воздушных судов США и численности населения Казахстана из главы и пустой запрос из условного примера.

Пустые запросы не удаляют: они показывают, что набор искали и не нашли. При обновлении реестра запросы журнала повторяют и сравнивают выдачу.

## Паспорт и список изменений

Два файла из главы [«Результат и поддержка»](../03-process/08-result-and-upkeep.md#как-записать) — их ведут рядом с реестром или картой:

- [passport.yaml](pathname:///templates/passport.yaml) — паспорт: название и описание, цель и владелец задачи, подход и границы, методы и охват опроса, состав по типам и режимам доступа, покрытие вопросов, пробелы, правило общедоступной части, составители и контакт, владелец процесса, план обновления (`upkeep` — что проверяют, как часто: `monthly`, `quarterly`, `annual` или событие, кто, даты последней и следующей проверки), даты, версия, лицензия, стандарт и файлы;
- [changes.csv](pathname:///templates/changes.csv) — список изменений, по строке на изменение: версия, дата, идентификатор записи, вид изменения (`new`, `changed`, `status`), поле, прежнее и новое значение, почему и кто внёс.

Значения в обоих файлах — условный пример из главы: паспорт первой версии и изменения, найденные при обновлении через полгода. Версию удобно называть месяцем выпуска — `2026-10`.
