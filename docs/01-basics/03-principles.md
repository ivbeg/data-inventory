# Принципы

Пять принципов проходят через всю книгу: каждый из них повторяется в главах о методах, процессе и практиках.

## 1. Цели и задачи определяют всё

Инвентаризацию начинают с конкретной задачи: запуск проактивных услуг, аналитика, межведомственная интеграция, открытие данных. От задачи зависят подход, методы и результат. Если задачи нет, инвентаризация превращается в сбор таблиц, которые никто не откроет. → [Зачем: цели инвентаризации](./02-goals.md)

## 2. Качество — часть инвентаризации

Найти набор недостаточно: нужно понять, годится ли он для задачи. Полнота, актуальность, согласованность с другими источниками проверяются во время инвентаризации, а не после. Качество важнее количества: десять проверенных наборов полезнее сотни строк в реестре без описаний. → [Качество данных](../03-process/07-quality.md)

## 3. Готовьтесь к разочарованию

Данных, которые должны быть по закону, может не оказаться. Данные, которые есть, бывают неполными, устаревшими и противоречивыми. Владелец может не знать, что у него хранится, а описание системы — не совпадать с её содержимым. Это нормальный результат инвентаризации, а не её провал: он показывает, где работать дальше.

## 4. Data-first в проектировании

Новые системы проектируют от данных, а не от интерфейсов. Данные — долгосрочный актив, который переживёт любую конкретную информационную систему. Инвентаризация даёт для этого основу: известно, какие данные уже есть и какие нужно собирать. → [Семь шагов](../03-process/01-steps.md#6-спроектировать-обновление-от-задач)

## 5. Непрерывность

Инвентаризация — не разовое мероприятие, а постоянный процесс в рамках управления данными. Системы закрываются и переезжают, владельцы меняются, законы обновляются. Из 136 адресов источников [атласа](../08-atlas/01-how-to-read.md) 2018–2019 годов к октябрю 2026 года у 29 исчезли домены. Реестр без даты проверки и без плана обновления через год вводит в заблуждение. → [Результат и поддержка](../03-process/08-result-and-upkeep.md)
