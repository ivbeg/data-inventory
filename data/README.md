# Приложения книги как данные

Первоисточник двух приложений: «Нормативная база» и «Чек-листы». Таблицы на страницах, CSV для Excel и лист для печати строит из этих файлов скрипт `scripts/appendices.mjs`. Правки вносят сюда, а не в страницы.

```
data/
  legal-acts.yaml   # реестр нормативных актов, на которые ссылается книга
  checklists.yaml   # чек-листы
```

```bash
npm run appendices        # проверить данные и пересобрать таблицы и файлы
npm run appendices:check  # только проверить
```

`npm start` и `npm run build` вызывают `npm run appendices` сами. Что строится — в git не хранится:

| Файл | Что в нём | Где показан |
|------|-----------|-------------|
| `docs/09-appendices/_generated/legal-where.mdx` | Страна → где проверять акт | «Нормативная база», «Где проверять акт» |
| `docs/09-appendices/_generated/legal-matrix.mdx` | Матрица «тема × страна» со ссылками на строки актов | «Темы и страны» |
| `docs/09-appendices/_generated/legal-response-times.mdx` | Сроки ответа на запросы | «Сроки ответа на запросы» |
| `docs/09-appendices/_generated/legal-<страна>.mdx` | Таблица актов страны и свёрнутый блок «Статьи и примечания» | Раздел страны |
| `docs/09-appendices/_generated/checklists-first.mdx` | Первый чек-лист из списка («Минимум») | «Чек-листы», до навигатора |
| `docs/09-appendices/_generated/checklists-navigator.mdx` | Таблица «шаг → чек-лист → когда открыть» | «Какой чек-лист когда» |
| `docs/09-appendices/_generated/checklists-rest.mdx` | Остальные чек-листы с заголовками | «Чек-листы» |
| `static/downloads/legal-acts.csv` | Реестр актов целиком | Ссылка на странице «Нормативная база» |
| `static/downloads/checklists.csv` | Пункты с колонками «чек-лист; пункт; глава; статус; кто; дата» | Ссылка на странице «Чек-листы» |
| `static/downloads/checklists.html` | Лист для печати — по чек-листу на лист A4 | Ссылка на странице «Чек-листы» |

CSV — для Excel в русской локали: кодировка UTF-8 с BOM, разделитель «;».

## Ссылки на главы

В обоих файлах ссылка на главу — путь от `docs/` и якорь заголовка: `03-process/06-access.md#запрос-владельцу`. Якорь — как его строит Docusaurus: текст заголовка `##`–`######` в нижнем регистре, пробелы — дефисы, знаки препинания убраны («Закрытые наборы — тоже в реестре» → `закрытые-наборы--тоже-в-реестре`).

Скрипт проверяет каждую ссылку:

- **нет файла главы** — ошибка, скрипт завершается с кодом 1;
- **нет заголовка с таким якорем** — предупреждение, ссылка в сгенерированной таблице ставится на начало главы, чтобы сборка не упала на битом якоре. Якорь стоит поправить в данных.

Подпись ссылки скрипт берёт из главы: в чек-листах — текст заголовка раздела, в реестре актов — название главы.

Скрипт проверяет и обратное направление: если глава ссылается на `02-legal-framework.md#…` или `04-checklists.md#…`, такой заголовок должен быть на странице или в данных. Поэтому заголовки чек-листов, на которые ссылаются главы, не переименовывают: «Перед началом», «Перед публикацией реестра», «Перед ссылкой на нормативный акт». Заголовки стран на странице «Нормативная база» (`## Казахстан` … `## Германия`) тоже обязательны. Новую страну добавляют в `COUNTRY_ORDER` и `COUNTRY_SHORT` скрипта, в `countries` и на страницу — заголовком и импортом `legal-<код>.mdx`.

## legal-acts.yaml

В начале файла — `checked`, общая дата проверки, и `countries` — четырнадцать стран и ЕС:

| Поле страны | Обязательно | Что писать |
|-------------|:-----------:|------------|
| ключ | да | Код: `kz`, `ru`, `eu`, `us`, `uk`, `fr`, `pl`, `kr`, `ee`, `fi`, `ca`, `cn`, `jp`, `de` |
| `name` | да | Название — совпадает с заголовком раздела на странице |
| `chapter` | да | Глава книги о стране; для ЕС, США, Эстонии, Финляндии, Канады, Китая, Японии и Германии — «Зарубежные методики» |
| `where` | да | Где проверять акт: официальная база и её замена, если она не открывается |
| `how_checked` | | Как сверяли акты этой страны: дата, база, что не открылось. Показывается в начале раздела страны |

Дальше — `acts`, одна запись на акт:

| Поле | Обязательно | Что писать |
|------|:-----------:|------------|
| `id` | да | Латиница, цифры, дефисы, с кодом страны впереди: `ru-8-fz`. Это и якорь строки акта на странице |
| `country` | да | Код страны |
| `title` | да | Название по-русски простыми словами: «Закон о доступе к информации» |
| `title_original` | | Официальное название — на языке оригинала; для России и Казахстана — по-русски, как в акте |
| `short` | да | Короткая подпись для матрицы: «№ 8-ФЗ», «FOIA», «GDPR» |
| `number` | да | Номер или реквизит: «Федеральный закон № 8-ФЗ», «5 U.S.C. § 552», «SI 2015/1415» |
| `date` | | Дата принятия: `2009-02-09`, `2018-10` или `2018` |
| `edition` | | Редакция, по которой читали, и изменяющие акты |
| `in_force` | | Дата вступления в силу; у `pending` — обязательна |
| `status` | да | `in_force` — действует, `repealed` — утратил силу, `pending` — не вступил в силу, `unverified` — не проверено |
| `status_checked` | да | Дата проверки статуса: `2026-10-25` или `2026-10` |
| `about` | да | О чём акт для инвентаризации — до 15–20 слов; длиннее 25 слов — предупреждение |
| `provisions` | | Список строк: статья — что в ней важно для описи. Показываются в свёрнутом блоке |
| `response_time` | | Срок ответа на запрос — у законов о доступе. Попадает в таблицу «Сроки ответа на запросы» |
| `topics` | да | Темы по важности, коды ниже. В матрицу «тема × страна» акт попадает по первым двум темам, если не утратил силу |
| `chapters` | да | Где акт работает в книге: список ссылок на главы с якорями |
| `url` | | Официальная публикация; если официальная база не открылась — копия, и об этом сказано в `note` |
| `links` | | Другие тексты: список `{title, url}` |
| `note` | | Примечание: как сверяли, что не удалось проверить, что изменится |

Неизвестное поле — ошибка: так ловятся опечатки.

Темы:

| Код | Тема |
|-----|------|
| `access` | Доступ к информации и запросы |
| `personal_data` | Персональные данные |
| `open_data` | Открытые данные и повторное использование |
| `sharing` | Обмен данными и защищённые данные |
| `systems` | Информационные системы и их учёт |
| `data_governance` | Управление данными и роли |
| `mandates` | Полномочия и структура органов |
| `statistics` | Статистика и формы сбора |
| `quality` | Качество данных |
| `standards` | Стандарты описания и метаданные |
| `archives` | Документы, архивы, вывод систем |
| `procurement` | Закупки и расходы на ИТ |
| `business` | Данные компаний |
| `ai` | Искусственный интеллект |

Пример:

```yaml
- id: ru-8-fz
  country: ru
  title: Закон о доступе к информации о деятельности государственных органов
  title_original: "Об обеспечении доступа к информации о деятельности государственных органов и органов местного самоуправления"
  short: № 8-ФЗ
  number: Федеральный закон № 8-ФЗ
  date: 2009-02-09
  edition: в редакции от 31.07.2025
  status: in_force
  status_checked: 2026-10-26
  about: Информация о деятельности органов, которую нельзя закрыть; запрос информации и срок ответа.
  provisions:
    - статья 18, часть 6 — запрос рассматривают в 30-дневный срок, отсрочка — не больше 15 дней
  response_time: "30 дней со дня регистрации запроса. Отсрочка — не больше чем на 15 дней сверх этого срока"
  topics: [access]
  chapters:
    - 03-process/06-access.md#запрос-владельцу
  url: https://www.consultant.ru/document/cons_doc_LAW_84602/
```

Строку с двоеточием и пробелом после него берут в кавычки: `about: "Сменил термины: …"`. Даты пишут без кавычек — скрипт читает их строками.

## checklists.yaml

`checklists` — список чек-листов в порядке семи шагов; первый показывается на странице до навигатора.

| Поле | Обязательно | Что писать |
|------|:-----------:|------------|
| `id` | да | Латиница, цифры, дефисы |
| `title` | да | Заголовок; из него получается якорь. Заголовки с входящими ссылками не меняют |
| `steps` | да | Шаги, к которым относится чек-лист: `[3]`, `[4, 5, 6]`; все семь — «все шаги» |
| `when` | да | Когда открыть — колонка навигатора |
| `intro` | | Одна-две фразы перед пунктами |
| `items` | да* | Пункты |
| `sections` | да* | Вместо `items` — разделы `{title, items}`, каждый со своим заголовком `###` |

\* Нужно одно из двух: `items` или `sections`.

Пункт:

| Поле | Обязательно | Что писать |
|------|:-----------:|------------|
| `text` | да | Проверяемое утверждение одной фразой: «Записана цель…». Одна проверка — один пункт. Можно ссылку на шаблон в Markdown и `код` в обратных кавычках |
| `chapter` | да | Глава, где пункт объяснён: строка или список ссылок |
| `label` | | Подпись ссылки, если не подходит заголовок раздела |

```yaml
- id: closed
  title: Перед тем как записать «закрыто»
  steps: [3]
  when: Данные не нашлись в открытом доступе
  items:
    - text: Проверено, не входит ли набор в то, что закрыть нельзя.
      chapter: 03-process/06-access.md#что-закрыть-нельзя
```
