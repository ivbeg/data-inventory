# PDF-версия книги

PDF собирается из готового сайта, а не из Markdown: так в нём те же схемы Mermaid, таблицы реестра, врезки и ссылки, что и на сайте. Скрипт перенесён из книги [«Каталоги данных»](https://github.com/ivbeg/data-catalogs-book) и упрощён: одна языковая версия, без интерактивных компонентов.

```bash
npm run build      # сайт в build/
npm run pdf        # PDF в build/data-inventory-book.pdf
npm run build:pdf  # обе команды подряд
```

На GitHub Actions PDF собирается при каждой публикации сайта (`.github/workflows/deploy-pages.yml`) и лежит рядом с ним: `https://datainventory.begtin.tech/data-inventory-book.pdf`.

## Что нужно

- Node.js 20 и новее, зависимости из `npm ci` (`playwright-core`, `pdf-lib`).
- Google Chrome 131 и новее: в нём работают номера страниц и колонтитулы CSS. Браузер Playwright не скачивается, используется установленный Chrome.
  - Другой путь к браузеру — переменная `CHROME_PATH`.
  - Chromium из Playwright — `npx playwright install chromium` и `PDF_BROWSER_CHANNEL=chromium`.
- Шрифты PT Serif, PT Sans и PT Mono. В macOS они есть, в Ubuntu — пакет `fonts-paratype`. Без них подставятся Georgia, Arial и Menlo, вёрстка поедет.
- Корейский шрифт для названий в главе «Южная Корея». В macOS он есть, в Ubuntu — пакет `fonts-noto-cjk`. Без него вместо корейских букв в PDF будут квадраты, а сборка не упадёт.

## Как устроено

1. `build-pdf.mjs` поднимает локальный сервер над `build/` и идёт по ссылкам «Следующая страница», начиная с главной. Порядок совпадает с боковым меню. Страницы категорий становятся титулами частей. Если категория ссылается на документ (`"link": {"type": "doc"}`, как у части VII), титул части ставится перед ним, а описание части берётся из `description` в `_category_.json`. Каждая категория из `docs/` должна стать частью, иначе сборка падает.
2. Каждая страница открывается в Chrome. Скрипт ждёт схем Mermaid и забирает только текст главы — без меню, оглавления и кнопок. Число схем сверяется с исходниками в `docs/`: если отрисованы не все, сборка падает.
3. Главы склеиваются в одну HTML-книгу: обложка, выходные данные, содержание, части, главы. «Об авторе» стоит в конце отдельно. Ссылки между главами становятся внутренними ссылками PDF, ссылки на прочие страницы сайта — абсолютными адресами.
4. Chrome печатает книгу дважды: после первого прохода из PDF читаются номера страниц глав, во втором они стоят в содержании.
5. `pdf-lib` добавляет закладки и метаданные из `CITATION.cff`.

Название, автор, лицензия и адреса берутся из `CITATION.cff`, подзаголовок и «Редакция …» — с главной страницы книги.

## Что настраивать

- Оформление — `print.css`: формат страницы (`@page { size: A4 }`), поля, шрифты, таблицы, код.
- Интерактивные компоненты — `INTERACTIVE_REPLACEMENTS` в `build-pdf.mjs`. Сейчас их нет; новый компонент нужно добавить туда, иначе в PDF попадут его кнопки.
- Параметры: `--out путь.pdf`, `--build-dir`, `--concurrency 4`, `--html путь.html` — сохранить собранную HTML-книгу для отладки вёрстки.
- `SOURCE_DATE_EPOCH` — дата сборки на обороте титула и в метаданных.
